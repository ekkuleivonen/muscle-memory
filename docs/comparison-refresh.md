## Work limits and expected cost

One scheduled invocation has a combined ten-minute deadline. Model refresh uses at most45seconds: up to100 current revisions,250 receipt GET attempts,32MiB declared receipt-object bytes,100 writes of128KiB maximum. It reuses existing offline results, never runs a model. Model snapshots expire after two hours, bind the current harness, and never fall back to raw receipts on a player request when enabled.

Human refresh first runs one fixed discovery query for all registered current non-synthetic revisions. Only potential groups with at least20 distinct starters get exact member queries. Discovery does not prove eligibility. Up to99 exact queries plus discovery (100 total), two builds concurrent, within the remaining whole-run deadline. Each exact query uses a server-selected interval bounded by publication and at most90days, a15-second transport deadline,1MiB response and1000-row limit; at most100 browser IDs undergo current CONTROL checks. Each metric separately needs20 eligible adult browser participants with exact revision/runtime/editor conditions and first/repeat separation. Unknown/minor/currently-excluded state is not counted.

Human artifacts expire after one hour. Serving requires conditional authorization of their generation on every read; an acknowledged opt-out/deletion invalidates old artifacts even within TTL. Missing, expired, mismatched, invalidated or interrupted data omits the comparison sentence. No stale fallback or request-triggered recomputation. More candidates than the work/deadline permits can temporarily lack a comparison; personal answers remain available.
